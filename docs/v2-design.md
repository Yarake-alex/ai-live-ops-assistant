# AI 直播运营助手 V2 设计说明

> 阶段一产物：仅设计文档，不含代码实现。
> V2 定位：**资料检索增强 + 开播准备工作流**。

---

## 1. V2 背景与目标

### 背景

V1 已完成直播运营 MVP 的核心链路：

- 商品资料：商品 CRUD、搜索筛选、CSV 导入导出（`/products*`）
- 商品资料文档问答：按商品上传 PDF/TXT/MD/CSV，商品维度 TF-IDF 检索 + 大模型回答（`/products/{id}/knowledge/*`）
- 开播话术：基于商品资料生成七模块主播话术（`/products/{id}/live-scripts`）
- 评论助手：模拟观众评论 → 主播口吻回复（`/products/{id}/comment-replies`）
- 直播复盘：固定四模块复盘，不编造未统计指标（`/products/{id}/live-reviews`）
- 直播素材库：通用资料上传与问答，已具备 embedding / 向量存储能力（`/rag/*`）
- 运营工作台：统计卡片 + 开播前 / 直播中 / 下播后三段流程入口

### 目标

V2 不是简单把"TF-IDF 换成向量知识库"，而是让系统更像直播运营人员**开播前真正使用的助手**：

1. **提升商品资料检索效果**：商品资料文档接入 Embedding + 向量检索，语义召回优于关键词匹配，同时保留 TF-IDF 作为可靠降级路径。
2. **形成轻量开播准备工作流**：用「商品资料完整度评分 + 开播前准备清单」把散落的页面能力串成"还差什么、先补什么"的工作流，不做任务系统。

---

## 2. V2 范围与非范围

### 范围内

- 商品资料文档 Embedding + 向量检索（上传即索引、问答优先向量、失败降级 TF-IDF）
- TF-IDF 降级链路（配置缺失 / 服务不可用 / 索引不完整 / 检索异常四层降级）
- 商品资料完整度评分（后端实时计算，不新增数据库字段）
- 开播前准备清单（基于真实数据生成，轻量工作流）
- 商品资料文档与直播素材库的边界说明（含未来混合检索的来源标注约定）

### 范围外（明确不做）

- 部门 / 主管 / 人事权限、复杂 RBAC、多租户 SaaS
- 手机 App / 小程序
- 真实直播平台接入（评论仍为界面模拟输入）
- Redis / Celery / Kubernetes / 消息队列
- 复杂数据大屏、趋势图可视化平台
- 删除账号能力（误建账号继续用「禁用」处理）
- 旧 CRM（客户管理 / 跟进分析 / 待跟进 / Agent 跟进助手，已下线不恢复）

## 3. 当前实现基础

### 商品资料文档接口已存在（V2 保留路径，不破坏前端）

| 方法 | 路径 | 现状 |
|---|---|---|
| POST | `/products/{id}/knowledge/upload` | 上传 + SQL 分块入库；同名文件先删旧 SQL 片段；**无向量索引** |
| GET | `/products/{id}/knowledge/documents` | 按商品列出文档（文件名 / 片段数 / 预览） |
| GET | `/products/{id}/knowledge/documents/{filename}/chunks` | 查看单个文件全部片段 |
| POST | `/products/{id}/knowledge/documents/{filename}/reindex` | **当前为诚实 no-op**：返回"商品知识库使用本地关键词检索，无需重建索引" |
| DELETE | `/products/{id}/knowledge/documents/{filename}` | 删除该商品下该文件 SQL 片段；**未清理向量**（当前也没有向量） |
| POST | `/products/{id}/knowledge/ask` | 商品维度 SQL 过滤 + `retrieve_chunks`（TF-IDF）+ 大模型回答 |

### 直播素材库已有 embedding / 向量能力（可复用其模式）

- `app/vector_store.py`：`VectorStore` 抽象（ChromaDB / pgvector 两实现），工厂 `get_vector_store()`，已支持 `add_chunks` / `search` / `delete_user_chunks` / `delete_filename_chunks` / `count_user_chunks` / `count_file_chunks`。
- `app/rag.py::retrieve_chunks_vector`：已实现四层降级链（配置开关 → 向量库不可用 → 索引不完整 → 检索异常），全部回退 TF-IDF。
- `app/embeddings.py`：`get_embedding_service()`，支持 `local` / `openai_compatible` / `test` 三种 provider。
- 上传/重建/删除素材时已有「先清向量再删 SQL、索引失败不影响主流程」的成熟模式，V2 商品资料文档可沿用同一套模式。

### 现状差距（V2 要补的）

1. 商品资料文档**只用 TF-IDF**，未接 embedding / 向量存储。
2. `VectorStore.search` 目前只按 `user_id` 过滤，**不支持按 product_id / source_type 过滤**（Chroma 元数据过滤可扩展；pgvector 实现的 embedding 存在 `document_chunks` 表，该表没有 product_id）。
3. 商品资料文档的重建索引是 no-op，删除/重传不涉及向量清理（因为还没有向量）。
4. 没有商品资料完整度评分与开播前准备清单能力。

### 边界声明

商品资料文档与直播素材库继续保持**两条独立链路**（详见第 8 节），V2 不合并、不混检。

## 4. 商品资料文档检索增强设计

### 4.1 上传即索引

`POST /products/{id}/knowledge/upload` 流程增强为：

1. 解析、分块（沿用 `split_text`，800 字符 / 120 重叠）；
2. 先删除该商品下同名文件的旧 SQL 片段（现有逻辑）；
3. 写入新 `product_knowledge_chunks` 片段并提交；
4. **尝试**为片段生成 embedding 并写入向量存储（沿用素材库的"索引失败不影响上传成功"模式，失败仅记录日志并留待「重建资料索引」补救）；
5. 向量不可用（`VECTOR_SEARCH_ENABLED=false`、服务初始化失败、embedding 配置缺失）时跳过第 4 步，商品问答自动走 TF-IDF。

### 4.2 问答优先向量、自动降级

`POST /products/{id}/knowledge/ask` 检索链改为：

1. **优先**：商品资料向量检索（按 `user_id + product_id + source_type=product_knowledge` 过滤）；
2. **降级 1**：向量未启用 / 向量存储不可用 / embedding 服务不可用 → 商品维度 TF-IDF（现有 `retrieve_chunks`）；
3. **降级 2**：向量检索返回空或不足 top_k，且该商品 SQL 片段数大于已索引数（索引不完整）→ 回退 TF-IDF；
4. **降级 3**：向量检索抛出异常 → 回退 TF-IDF；
5. 所有降级路径记录日志，前端不感知技术细节（文案用「资料检索」表述）。

问答默认只检索**当前商品**的资料文档，不混合检索直播素材库（见第 8 节）。

### 4.3 重建资料索引真实生效

`POST /products/{id}/knowledge/documents/{filename}/reindex` 在 V2 中：

1. 校验商品归属与用户隔离；
2. 清理该用户、该商品、该文件的旧向量索引；
3. 读取该文件全部 SQL 片段重新生成 embedding 并写入向量存储；
4. 返回 `{"reindexed": true, "filename": ..., "chunks": N}`；
5. 向量未启用时保持返回"未启用"类消息（文案沿用前端「资料索引功能未启用」风格，不出现技术词）。

### 4.4 同名重传与删除的索引清理

- **同名文件重传**：先清理该商品下同名文件的旧 SQL 片段（已有）**和旧向量索引**（新增），再写新片段、建新索引。
- **删除资料文档**：删除 SQL 片段后，同步清理该用户、该商品、该文件的向量索引；清理失败不影响删除结果，但要在响应中给出可感知提示（沿用素材库 `vector_warning` 模式）。

### 4.5 接口与前端兼容

- 保留全部现有路径，不破坏前端现有调用。
- 前端「重建资料索引」按钮与状态文案已在 V1 收尾中改为运营语言，V2 无需再改文案体系。

### 4.6 向量存储实现备注（设计决策，阶段二细化）

- **ChromaDB（SQLite/开发）**：**优先使用独立 collection**（建议名 `product_knowledge_chunks`），与通用素材库的 `rag_chunks` collection 物理隔离，元数据含 `user_id`、`product_id`、`filename`、`chunk_index`、`source_type=product_knowledge`。若未来复用单 collection，必须满足两个硬性条件：① id 使用 namespaced 前缀（如 `product_knowledge:{chunk_id}`），避免与通用素材库 `DocumentChunk.id` 撞车；② 检索必须强制带 `source_type + user_id + product_id` 过滤，防止跨来源、跨商品召回。
- **pgvector（PostgreSQL/生产）**：现有 embedding 列在 `document_chunks` 表，无 `product_id`。两个候选方案：
  - A（推荐）：`product_knowledge_chunks` 表增加 `embedding vector(N)` 列，与通用素材分表分列，过滤条件走 SQL（`user_id + product_id`）；
  - B：pgvector 模式下商品资料也存入 Chroma——引入混合部署复杂度，不推荐。
- `VectorStore` 抽象需增加商品维度的写入 / 检索 / 删除方法（或通过可扩展的 `metadatas` + `where` 过滤参数实现），具体接口形态在阶段二定稿。

## 5. 数据与权限隔离

沿用 V1 隔离原则并落到向量索引元数据上：

| 隔离维度 | 规则 |
|---|---|
| `user_id` | 所有业务数据只属于当前用户；普通 user 只能访问自己的商品与资料 |
| `product_id` | 商品资料（SQL 片段与向量索引）必须绑定商品，问答只召回当前商品 |
| `filename` | 同一文件的重传 / 删除 / 重建按文件名幂等处理 |
| `chunk_index` | 片段序号随 SQL 片段同步，保证索引与 SQL 一一对应 |
| `source_type` | 向量元数据固定 `source_type = product_knowledge`，与直播素材库（通用素材）区分 |

硬性要求：

- **不允许跨用户召回**（向量检索必须带 `user_id` 过滤）。
- **不允许跨商品召回**（向量检索必须带 `product_id` 过滤）。
- admin 仅管理账号（创建 / 禁用），**不默认跨用户查看业务资料**。
- 所有新增接口沿用 `get_current_user` + `get_product_for_user` 的归属校验模式。

## 6. 商品资料完整度评分设计

### 原则

- 后端**实时计算**，不新增数据库字段。
- 先用**确定性规则**，不引入复杂 NLP，不调用额外大模型分析。
- 输出结构（示意）：

```json
{
  "score": 58,
  "missing_items": ["商品资料文档", "售后规则", "风险边界"],
  "suggestions": [
    "上传商品 FAQ 资料文档",
    "补充售后规则文档",
    "在备注中写明不可承诺的内容"
  ]
}
```

### 评分维度（建议权重为均分，逐项命中计分）

| 维度 | 判定依据（确定性规则） |
|---|---|
| 商品名称 | `name` 非空（必填，默认命中） |
| 价格 | `price > 0` |
| 库存 | `stock > 0` |
| 直播状态 | `live_status` 已设置 |
| 核心卖点 | `selling_points` 非空 |
| 适用人群 | `target_audience` 非空 |
| 用户痛点 | `pain_points` 非空 |
| 优惠信息 | `promotion` 非空 |
| 商品资料文档 | 该商品至少 1 个知识片段 |
| FAQ 或问答资料 | 文件名含 `faq` / `问答` / `Q&A`（大小写不敏感）的文档存在 |
| 售后规则 | 文件名含 `售后` / `退换` / `after` 的文档存在 |
| 风险边界 / 禁用话术 / 不可承诺内容 | `notes` 非空，或文件名含 `风险` / `边界` / `禁用` / `不可承诺` / `合规` 的文档存在 |

- `score = 命中维度数 / 总维度数 × 100`（取整）。
- `missing_items` = 未命中的维度名称（用运营语言，如「售后规则」而不是字段名）。
- `suggestions` = 按缺失项映射的固定建议文案（确定性映射表，不用大模型生成）。

### 边界

- 评分只做参考，不阻塞任何现有功能（资料不全仍可生成话术/问答，现有兜底机制继续生效）。
- 不做"评分历史记录""评分对比"等复杂能力。

## 7. 开播前准备清单设计

### 原则

- 目标是**轻量工作流**，明确**不做任务系统**：不新增待办分配、负责人、截止时间、提醒、审批等能力。
- 清单**根据真实数据动态生成**：哪一项完成、哪一项缺失，由后端实时计算返回，不落库。

### 状态定义

| 状态 | 含义 | 判定 |
|---|---|---|
| `done` | 已完成 | 对应数据存在 / 已生成 |
| `todo` | 待补充 | 对应数据缺失 |
| `recommended` | 建议处理 | 有数据但质量待提升（如完整度低于建议阈值、缺少上场复盘建议） |

### 检查项（建议清单）

1. 已选择主推商品（对应页面已有选中商品交互）
2. 商品基础资料已完善（核心字段非空）
3. 商品资料文档已上传（至少 1 个片段）
4. 商品资料完整度达到建议阈值（建议 80 分）
5. 开播话术已生成（该商品存在 `success` 或 `fallback` 状态的 live_script）
6. 常见问题已准备（FAQ 类文档存在，或该商品有评论回复记录）
7. 风险提醒已确认（风险边界维度命中）
8. 已有上场复盘建议（判定：该商品存在复盘记录，且复盘内容含"下场直播优化建议"模块；V2 不新增已读/查看状态字段，不做"已查看"判定）

### 展示建议（阶段五前端细化）

- 运营工作台：每个状态给一个计数徽标（如"开播准备 5/8"），点击进入商品资料页。
- 商品资料页：选中商品后展示清单与完整度，缺什么直接给入口按钮（如"去上传资料文档"）。

## 8. 商品资料文档与直播素材库关系

| | 商品资料文档 | 直播素材库 |
|---|---|---|
| 绑定关系 | 绑定**具体商品**（product_id） | 通用，只绑定用户 |
| 服务场景 | 商品问答、开播话术、评论助手、直播复盘 | 品牌介绍、通用售后政策、活动规则、直播间统一话术规范、禁用承诺/合规规则 |
| 检索范围 | 只检索当前商品资料 | 只检索本用户全部通用素材 |
| 向量元数据 | `source_type=product_knowledge` | 现有元数据（user_id / filename / chunk_index） |

约定：

- **V2 默认商品问答只查商品资料文档，不混合检索直播素材库。**
- 若未来支持混合检索（V2 之后），回答的 `sources` 必须标明来源类型（`商品资料` / `直播素材`），且仍遵守 user 隔离。

## 9. 接口建议

### 保留

- 商品资料文档全部现有接口（路径、方法、现有响应结构不变）。
- 直播素材库 `/rag/*` 全部现有接口不变。

### 新增（轻量，仅 1 个）

- `GET /products/{id}/readiness`（备选名 `GET /products/{id}/live-prep`，阶段四定稿）
  - 返回：`completeness`（第 6 节结构）+ `prep_checklist`（第 7 节结构）。
  - 归属校验：`get_product_for_user`，仅当前用户可见。

### 前端文案约束

- 用户可见文案**不得出现**"向量 / TF-IDF / Embedding / RAG"等技术词。
- 统一使用运营语言：**资料整理、资料检索、资料索引、开播准备、资料完整度**。
- 技术词只允许出现在代码注释、日志与开发者文档（如本文档）中。

## 10. V2 验收标准

### 后端

- [ ] 没有 Embedding 配置时，商品资料问答仍可用（TF-IDF 降级）。
- [ ] 有 Embedding 配置时，上传资料后可语义检索（可用同义问法验证召回）。
- [ ] 「重建资料索引」真实生效：重建后该文件向量数与 SQL 片段数一致。
- [ ] 删除资料文档、同名重传后，不残留旧向量索引。
- [ ] 不跨用户、不跨商品泄露资料（双账号测试 + 商品间测试）。
- [ ] 商品资料完整度返回 `score`（百分比）、`missing_items`、`suggestions`。
- [ ] 开播准备清单随真实数据变化（上传文档后 `todo → done`）。

### 前端

- [ ] 运营工作台能看到资料完整度或开播准备状态。
- [ ] 商品资料页能看到完整度、缺失项与建议。
- [ ] 商品资料文档仍能上传、查看、删除、问答。
- [ ] 直播素材库仍可用，且不喧宾夺主（保持次级入口定位）。
- [ ] 普通运营用户界面上不暴露技术词。

### 测试

- [ ] 商品资料文档向量检索测试
- [ ] TF-IDF 降级测试（四层降级链逐层覆盖）
- [ ] 重建资料索引测试
- [ ] 用户隔离测试（跨用户不可召回）
- [ ] 商品隔离测试（跨商品不可召回）
- [ ] 删除 / 重传索引清理测试
- [ ] 资料完整度计算测试（含边界：空商品、全维度命中）
- [ ] 开播准备清单状态测试（todo / done / recommended 判定）
- [ ] 现有全量测试继续通过（V1 行为不回归）
