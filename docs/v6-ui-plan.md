# V6 UI 统一与体验优化计划（2026-08）

> V6 目标：在不改变业务功能、不改后端接口、不改数据库的前提下，把 Vue3 前端从「能用的迁移版」提升为「适合演示的轻量 SaaS 运营后台」。
> 约束：不新增/不删除业务功能；不引入 UI 框架与状态库；旧 `static/index.html` 保留（`/legacy`）；每阶段小步提交、可运行、可回退。

## 一、UI 基线审查结论（阶段 0 输出）

审查范围：`frontend/src` 全部 30 个文件（App.vue、AppShell、LoginView、HomeView、5 个业务视图、21 个组件）。功能全部可用，问题集中在视觉一致性与观感层面，共 9 类：

### 1. 布局
- 各页面最大宽度不统一：工作台 1100px、素材库 960px、商品资料 1200px、评论助手 1200px、用户管理 1000px → 统一 1200px 内容区。
- 商品资料页纵向卡片堆叠无分区导航，长页缺少位置感；评论助手/用户管理双栏在 900px 以下才折叠，768px 平板仍显拥挤。
- 移动端（<480px）商品选择器头部、统计卡、双栏布局有溢出风险。

### 2. 导航
- 主导航是一排「按钮组」（App.vue 内 `page-nav`），与页头分离，观感像工程页而非后台导航。
- 导航中含「骨架页」入口，HomeView 文案仍是「V5 阶段 2：业务页面尚未迁移」——未完成感文案，必须移除或改为「关于/版本信息」。
- 当前用户仅以「已登录：xxx」文本呈现，修改密码/退出按钮无状态区分。

### 3. 卡片
- 卡片结构可用（标题 + 操作 + 内容），但各组件重复手写 `.card` / `.card-head`，圆角 6/8/10px 混用，边框/背景色硬编码。
- 商品资料页 8 张卡片没有统一的「标题区 / 操作区 / 内容区 / 状态区」视觉节奏。

### 4. 表单
- input/select/textarea 大量依赖浏览器默认样式：大多只有 `width:100%` + `font-size:13px`，无 padding、border、hover/focus 态（登录页输入框完全是浏览器默认）。
- 全部用 placeholder 代替 label，label 与输入框无程序关联。
- 表单校验反馈用原生 `alert()`，观感差。

### 5. 按钮
- `.primary-btn` / `.light-btn` / `.danger-btn` / `.outline-btn` / `.success-btn` 在 20+ 个组件中重复定义，尺寸（4px10px / 6px14px / 6px16px）与字号（11-14px）混乱。
- 主操作色不统一：多数为蓝 #2563eb，但资料问答、上传按钮为绿 #16a34a，语义混乱。
- 危险操作（删除/清空/禁用）红底白字与普通按钮区分度不足；禁用态只有 opacity，无明确视觉。
- 上传按钮、生成按钮等主操作缺乏一致的「按钮 + 状态文字」组合。

### 6. 空态
- 空态文案完整（「暂无商品…」「选择商品后…」），但样式单薄（灰色小字居中），且大多缺少明确的下一步动作引导（唯一例外：商品选择器有「请先新增或导入商品」）。

### 7. 加载/错误状态
- 全部为「加载中…」灰字 + 失败红字，无骨架/重试动作；各组件加载态样式分散重复（`.hint` / `.hint-error`）。
- 大量操作反馈依赖 `alert()` / `confirm()`（删除、清空、导入汇总、整理结果），无统一轻提示。

### 8. 响应式
- 全局仅 3 处 `@media (max-width: 900px)` 断点；无 320px / 768px / 1024px 分档；按钮文字在 320px 下存在溢出风险（长文件名、统计卡并排）。

### 9. 可访问性
- 纯图标关闭按钮（✕）无 aria-label；弹窗无 role/tabindex 管理。
- 状态表达部分依赖颜色（运营建议优先级标签有文字；资料完整度百分比+颜色+文字，尚可），需阶段 7 全面复核。
- focus 态缺失：自定义按钮/输入框覆盖浏览器默认样式处没有替代 focus 样式。

## 二、设计方向（V6 视觉基调）

- 轻量 SaaS 运营后台，专业、清爽、信息密度适中；不做营销页、不做大屏、不用大面积渐变、不多阴影、不过度圆角。
- 色彩以中性色为主（灰阶 #f9fafb/#f3f4f6/#e5e7eb/#9ca3af/#6b7280/#111827），蓝 #2563eb 为唯一主操作色；绿/黄/红只用于状态语义（成功/警告/危险）。
- 卡片圆角统一 8px，阴影最多一层浅投影；间距 4px 基线网格。
- 页面内容区统一 1200px 上限，移动端不溢出。

### 全局视觉规范补充（2026-08-17 用户追加确认）

- **背景（全站统一）**：所有页面（含登录页）统一浅冷灰蓝底 `--bg: #f5f7fb`；内容区顶部仅保留极淡蓝白 → 浅灰蓝的克制过渡；禁止明显渐变、光球、网格、噪点、插画背景与玻璃拟态；背景只为拉开白面板与底色的层次，不抢注意力。
- **内容区**：`--content-max: 1180px` 统一上限、桌面居中；窄屏保留左右内边距；顶栏、主导航与页面主体共享同一条左右对齐线（统一走 token，禁止各页宽度不一）。
- **白色业务面板**：`--panel-bg #fff`、边框 `--panel-border #e8edf5`、圆角 6–8px、**默认无阴影**（确需层级时仅用极弱阴影）；只有筛选区/表单区/列表区/编辑器区/统计区等独立业务单元使用白色面板；**禁止卡片内再套卡片**。
- **顶部导航**：顶栏与主导航白底 + 细分割线与内容背景分隔；激活项蓝字 + 2px 底边（不靠颜色/加粗区分）；导航热区高度 ≥36px；用户信息/修改密码/退出登录保持低强调层级。
- **各页布局要点（落入阶段 3–6）**：商品资料——筛选/商品选择/直播概览/资料文档按统一网格排布、左右列对齐、空态位于对应业务面板内；素材库——列表/搜索/上传/问答统一面板样式、内容铺满不悬左上角；评论助手——输入与历史两栏高度/顶对齐/面板间距一致；用户管理——新增与列表稳定双栏、宽屏列表充分利用空间。

## 三、分阶段计划

### 阶段 0：UI 基线审查与计划（本阶段）
- 输出：本文档。
- 提交：`docs: prepare v6 ui refinement plan`。

### 阶段 1：基础视觉系统（`style: add v6 base ui system`）
- 新建 `src/styles/base.css`（全局）：
  - CSS 变量：`--color-*`（中性色阶、primary #2563eb、success/warning/danger 及其浅底）、`--radius`（8px/6px/999px）、`--shadow`、`--space-*`、字体栈。
  - 统一基础元素全局样式：button（primary/light/danger/success 变体类）、input/select/textarea（统一 padding/border/focus/hover/disabled）、label、.card、.badge（tag/status）、.alert（info/warn/error）、.empty（空态容器）、.hint / .hint-error、.muted。
  - 全局 focus-visible 样式；按钮/表单去除浏览器默认外观。
- 各组件先删重复的本地按钮/卡片样式，切换为全局类（不重写结构、不改逻辑）。
- 验收：`npm run build` 通过；全部页面按钮/表单外观统一；无组件残留硬编码按钮色。

### 阶段 2：应用布局与导航（`style: refine app shell navigation`）
- AppShell 重构视觉：顶栏含产品名 + 当前用户 + 修改密码 + 退出登录；主导航移入 AppShell（横向导航条），active 态用蓝色下划线/底色。
- 移除「骨架页」导航入口与 HomeView 占位文案（改为「关于/版本信息」入口，内容为产品一句话介绍 + 版本 + /legacy 回退说明）；App.vue 同步调整。
- 主内容区统一 `max-width: 1200px`；移动端导航允许换行（flex-wrap），不引入菜单库。
- 验收：导航与各页入口正常、无未完成感文案；`npm run build` 通过。

### 阶段 3：运营工作台优化（`style: polish operations dashboard`）
- 强化「今天该做什么」：欢迎区 → 三步任务引导（完善资料 → 生成话术 → 评论/复盘）。
- 开播准备横幅改为蓝色浅底 alert 样式（不用渐变），按钮为主操作样式。
- 6 个统计卡统一尺寸/图标/标题/数字/说明；数字为 0 时显示引导文案（如「暂无商品，去新增」）。
- 直播流程三卡改为任务清单样式（编号/勾选图标 + 动作链接列表），保留原有跳转入口。
- 验收：结构不变、跳转不变；空数据有明确下一步；`npm run build` 通过。

### 阶段 4：商品资料页信息架构优化（`style: polish product knowledge page`）
- 保留纵向卡片布局（不恢复 Tabs）。
- 新增页内锚点分区导航（sticky 顶部）：商品基础 / 开播准备 / 资料文档 / 问答洞察 / 话术复盘（纯锚点，不引路由）。
- 商品选择区与商品详情区优化：头部工具栏（新增/导入导出归位）、详情字段排版（卖点/人群/痛点用键值行）；筛选/商品选择/直播概览/资料文档按统一网格排布、左右列对齐；空态位于对应业务面板内；无卡片套卡片。
- 开播准备概览条、资料完整度、资料文档、资料问答、问题洞察、运营建议、直播话术、直播复盘卡片统一为「标题区 / 操作区 / 内容区 / 状态区」结构。
- 验收：分区锚点可用；接口调用不变；`npm run build` 通过。

### 阶段 5：素材库与评论助手优化（`style: polish material and comment pages`）
- 素材库：搜索/列表/上传区/片段预览/资料问答统一面板样式并铺满内容区（内容少时不能只有一个小白框悬在左上角）；「重新整理」「清空全部」等危险操作用 danger/outline 区分；空态提供「上传素材」动作引导。
- 评论助手：保持两栏；两栏高度、顶部对齐与面板间距一致；商品选择 + 快捷问题用 tag 按钮组；结果区加状态 badge（成功/本地兜底/失败）与更好的可读性排版；历史项「查看」当前查看状态高亮。
- 验收：交互与接口不变；`npm run build` 通过。

### 阶段 6：用户管理与登录页优化（`style: polish auth and user management`）
- 登录页：居中卡片、产品名与说明、输入框带 label 与统一样式、错误提示用 alert 样式、背景改中性浅色（去渐变）。
- 用户管理：新增用户表单用 label 分组；用户列表行统一（用户名/角色 badge/状态 badge/创建时间/操作）；稳定双栏布局，宽屏下列表充分利用空间；禁用确认与危险操作按钮统一。
- 修改密码弹窗与其他弹窗统一为同一套弹窗样式。
- 验收：`npm run build` 通过。

### 阶段 7：响应式、可访问性与最终验证（`docs: finalize v6 ui refinement notes`）
- 视口走查：320 / 768 / 1024 / 1440；按钮文字不溢出、双栏正确折叠。
- 表单 label 与输入框关联（for/id 或 aria-label）；Tab 键可达；focus 态可见。
- 颜色语义复核：状态不只靠颜色（badge 均有文字）。
- `npm run build`；后端全量 pytest（收尾回归）；Docker 入口烟测（`/`、`/legacy`、`/health`、`/auth/me`）。

## 四、明确不做的事

- 不修改后端接口路径/参数/返回结构；不修改数据库模型；不读取/修改 `.env`。
- 不删除 `static/index.html` 与任何文件；不新增业务功能。
- 不引入 Element Plus / Ant Design Vue / Naive UI 等 UI 框架；不引入 Pinia / vue-router。
- 不重写业务逻辑与 API client；只做样式与组件结构级调整。
- 不处理旧页面 `static/index.html`（继续作为 `/legacy` 保留）。
